Planifier le code pour un jeu en JavaScript. Le jeu consiste en un fichier JavaScript et une inclusion d'un fichier qui s'appelle level.yaml. Le fichier level.yaml contient un nombre de niveaux. Il est déterminé par un en-tête name, qui est son nom, puis par une liste de n_level, donc il y aura aussi dans l'en-tête num_level qui est égal au nombre de level qu'il y a dans le fichier. Puis en dessous, une section level_1 qui contient un tableau de 5x5 entrées, donc 5 listes de 5 items. Chaque item codifie un niveau, donc il est considéré comme en fait un carré de 5x5. Et bien évidemment, ce carré de 5x5 va avoir des tuiles, donc chaque tuile va être référencée par son index, donc A B C D E F pour les colonnes, 1 2 3 4 5 pour les lignes. Et donc à chaque entrée, il y a un numéro de tile, donc qui est après dans une liste dans le fichier principal JSON qui définit les différents types de tuiles et chaque tuile bien évidemment aura une action particulière. L'idée étant dans le jeu systématiquement de partir d'une tuile de début et d'arriver à une tuile de fin. De nombreux items permettent ou pas de se téléporter, de déplacer, de bouger ou pas des blocs en fonction de leur catégorie. Donc ces catégories sont à définir dans un deuxième temps. Donc c'est le fichier level.yaml qui doit être constitué de cette manière et donc appelé par le code principal pour charger les niveaux. Dans chaque level.yaml, il y a un en-tête qu'il faudra mettre à jour qui est le score golf, qui est le nombre minimal d'entrées qu'il y aura eu pour finir ce niveau. Donc le score golf est le meilleur score qu'un joueur a pu faire pour aller du début à la fin en utilisant le moins de déplacements, donc d'entrées au bas possible, ainsi que éventuellement une touche action qui sera définie plus tard. Donc voilà pour la présentation de ce fichier-là et donc le moteur de jeu en fait fera des actions en fonction du type de tuile et décidera si le joueur peut passer de la tuile du début à la fin, calculera le nombre de coups et mettra à jour donc ce fichier en ayant chargé préalablement. Voilà la base du jeu. Maintenant, fais un plan de définition de code autour de ça pour des agents de manière à ce que l'on puisse l'utiliser plus tard pour exécuter le code.


## 🎮 Planification de l'Architecture du Jeu JavaScript

---

### 📂 1. Définition des Formats de Données (`level.yaml` & `tiles.json`)

Le système repose sur une séparation stricte entre la définition des niveaux (YAML) et la configuration comportementale des tuiles (JSON/JS).

#### Fichier `level.yaml`

```yaml
name: "Labyrinthe 5x5 Tactique"
num_level: 2
levels:
  level_1:
    golf_score: 4
    grid:
      - [1, 0, 0, 0, 2] # Ligne 1 (Colonnes A, B, C, D, E)
      - [0, 5, 0, 4, 0] # Ligne 2
      - [0, 0, 3, 0, 0] # Ligne 3
      - [0, 4, 0, 5, 0] # Ligne 4
      - [0, 0, 0, 0, 9] # Ligne 5

```

#### Fichier de Configuration des Tuiles (`tiles.json`)

Chaque ID numérique de la grille correspond à un comportement modulaire :

* **0** : Tuile vide (Passage libre)
* **1** : Tuile de départ (`Start`)
* **2** : Tuile d'arrivée (`End`)
* **3** : Mur infranchissable (`Wall`)
* **4** : Bloc déplaçable (`MovableBlock` - catégorie A)
* **5** : Téléporteur (`Teleporter`)

---

### ⚙️ 2. Architecture Logicielle & Design Patterns

Pour structurer ce moteur de jeu de manière robuste et extensible, nous appliquons les patrons de conception (Design Patterns) suivants :

| Composant Principal | Rôle et Responsabilité | Pattern Recommandé |
| --- | --- | --- |
| **Loader** | Parse les fichiers YAML (`js-yaml`) et JSON pour initialiser les niveaux en mémoire. | *Facade Pattern* |
| **GameEngine** | Gère la machine à états du jeu, la position du joueur, le compteur de coups et la condition de victoire. | *State Pattern* / *Mediator* |
| **TileRegistry** | Associe chaque ID de tuile à une stratégie d'action spécifique (déplacement, téléportation, poussée). | *Strategy Pattern* |
| **InputController** | Écoute les événements clavier (flèches + touche action) et abstrait les commandes. | *Command Pattern* |

---

### 🛠️ 3. Plan d'Implémentation par Modules (Pour Agents)

Ce plan découpe le développement en modules autonomes exécutables séquentiellement par des agents de codage :

#### 🔹 Module A : Chargement et Parsing (`levelLoader.js`)

* **Objectif** : Importer `level.yaml` à l'aide d'une bibliothèque comme `js-yaml` et valider la structure 5x5.
* **Fonctions clés** :
* `loadLevelData(url)` : Charge et retourne l'objet JavaScript parsé.
* `getGrid(levelIndex)` : Extrait la matrice 5x5 correspondante aux coordonnées de colonnes (`A`-`E`) et lignes (`1`-`5`).



#### 🔹 Module B : Moteur de Jeu et Règles (`GameEngine.js`)

* **Objectif** : Gérer la logique de déplacement et l'interaction avec les tuiles.
* **Fonctions clés** :
* `movePlayer(direction)` : Calcule la nouvelle position `{x, y}`, vérifie les collisions via le registre de tuiles.
* `checkWinCondition()` : Vérifie si la position actuelle correspond à la tuile `End`.
* `updateGolfScore()` : Compare le nombre de coups actuel avec le `golf_score` du YAML et met à jour si un nouveau record est atteint.



#### 🔹 Module C : Contrôleurs et Interface (`uiRenderer.js`)

* **Objectif** : Afficher la grille 5x5 dans le DOM ou sur un Canvas HTML et réagir aux entrées utilisateur.
* **Fonctions clés** :
* `renderGrid()` : Génère l'affichage visuel basé sur les coordonnées A1-E5.
* `updateHUD()` : Affiche en temps réel le nombre de coups et le score golf cible.

## 🗺️ Analyse du Niveau 1 (Tutoriel)

Pour cette version 1 de démonstration, le Niveau 1 met en scène un parcours d'initiation sur une grille de 5x5 cases (colonnes de **A** à **E**, lignes de **1** à **5**).

### 🧩 Types de tuiles utilisés (6 types)

1. **`0` - Tuile vide (Sol libre) :** Espace de circulation standard sans contrainte.
2. **`1` - Tuile de Départ (`Start`) :** Position initiale obligatoire du joueur (située en **A1**).
3. **`2` - Tuile d'Arrivée (`End`) :** Objectif final du niveau (situé en **E5**).
4. **`3` - Mur (`Wall`) :** Obstacle infranchissable (placé en **C3** au centre) obligeant à contourner la zone.
5. **`4` - Bloc Déplaçable (`MovableBlock`) :** Élément interactif qui peut être poussé si le joueur dispose de l'action adéquate.
6. **`5` - Téléporteur (`Teleporter`) :** Permet un saut instantané d'une coordonnée à une autre.

### 🛤️ Type de parcours

* **Parcours tactique linéaire avec embranchement :** Le joueur part de **A1**, se déplace le long des couloirs dégagés, doit gérer l'obstacle central (**C3**) en contournant par les côtés ou en interagissant avec le bloc déplaçable (**4**), puis utilise le téléporteur (**5**) ou le chemin libre pour atteindre la case d'arrivée en **E5**. Le score golf optimal est fixé à 4 ou 6 mouvements selon la stratégie choisie.
